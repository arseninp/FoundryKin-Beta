# FoundryKin

Мобильный редактор текстур Minecraft Bedrock: Find, 3D-просмотр, рисование PNG, импорт/экспорт .mcpack.

Приложение: https://arseninp.github.io/FoundryKin-Beta/app.html

## Статус на 2026-11-01

Проверенный кодовый HEAD перед обновлением документов: 62c8af15ec1fb4d9c4cc1c96caec9e349141df6a. Это не выпуск приложения. Рефакторинг и модельный этап не завершены. По прежней проверке основной UI остаётся на legacy fk-модулях 0.9.1; HTML в этой передаче не перечитан. Новый catalog/models ещё не принят в основном редакторе.

Повреждение пакета хоруса 5c5f9f4 исправлено в 86b6d8f: восстановлены границы модулей, настоящая shared dependency и тесты. Прежний блокер больше не текущая задача. Далее записаны cave vines с berries; индексированные состояния copper bulbs/frosted ice/respawn anchor; нормализация front трёх пар печей; специализированное dragon egg; связи форм bamboo/shoot и torchflower/crop; общий stem для стеблей тыквы и арбуза с growth/attached/facing.

Следующая согласованная задача — одна карточка тыквы с её стеблем и одна карточка арбуза с его стеблем, с явным просмотром «Без стебля / Со стеблем». Во втором варианте видны плод и соседний стебель вместе. Эта связь и составной просмотр пока не записаны; общий builder stem сам карточки не объединяет. Работа продолжается небольшими проверяемыми пакетами в новом пути, не в legacy.

Новый путь разделяет данные, ownership, aliases/forms/states, исходные ID и построение моделей. Edit PNG не управляет геометрией/стадиями; индексы и повторы сохраняются. Предыдущие реализованные модели и ограничения описаны в CONTEXT/ARCHITECTURE; повторять их из устаревших чеклистов не нужно. Unknown не подменяется кубом. Entities требуют общего source adapter и отложены.

Прочитаны OLDCHAT14 целиком и все шесть документов; проверены история, полные diff исправления хоруса/stem и текущие forms. Тесты в этой передаче не запускались. Исторические целевые тесты не равны полным validate/tests/compile/CI и PNG/WebGL/Android/export. Свежего полного остатка нет; ожидаемые 99 registry types в тесте не означают 99 готовых карточек или завершённый рефакторинг.
