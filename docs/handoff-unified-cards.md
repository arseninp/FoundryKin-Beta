## Приоритет 1 — семейные наборы

Восстановить контракт существующих наборов, а не реализовывать второй каталог. Проследить source definitions → compiled records/families/cards → access/search → form controls → reopen/export. Сопоставить действующие определения семейств, включая data/catalog-families и существующий preview path. Не угадывать группировку по acacia-префиксу и не считать всякую отдельную карточку автоматически лишней: определить именно предусмотренные семейные связи.

Приёмка блока:
- Одна карточка предусмотренного семейства в Find, формы выбираются внутри, а не рассыпаются отдельной выдачей.
- Alias/source search приводит к правильной семейной карточке; сохранённый obj/path открывает правильный источник, форму и texture slot.
- Все реальные source IDs и owned/carried/icon/indexed resources доступны; shared dependencies не становятся чужими редактируемыми файлами.
- Изменение формы не теряет рисунок и history; Add/reopen/export сохраняют правильные пути. Не скрывать дефект удалением records или PNG.
- Проверить аметист как один кристалл выбранной стадии, стадии культур и berries у cave vines; после default switch эти сценарии не подтверждены.

## Приоритет 2 — переключение без лишней работы

Статически в 0a502af:
1. selectCompiled перед каждой готовой selection вызывает packCur; packCur кодирует текущие frames в PNG через toDataURL даже без новой правки.
2. prepareEditorImages создаёт canvases/frames для required paths при каждом вызове; при same-card switching существующие fr[path] сохраняются, и часть созданных кадров затем не используется.
3. selectCompiled очищает модель до await и затем строит её заново; slot change тоже идёт через этот путь. Изображения имеют cache, поэтому не утверждать «каждый раз скачивает всё».

Это адреса для измерения/сокращения работы, не установленная доля каждого участка в задержке. Не ломать ownership, borrowed resources, async invalidation, history или сохранённые PNG ради скорости. Не добавлять ещё один runtime/cache manager без необходимости.

## Приоритет 3 — завершить чистку, а не объявить её завершённой

После проверки семейств и переключения удалить подтверждённо неиспользуемый legacy: сначала зависимости и HTML connections, потом физические файлы/старые exports, согласованно с существующими тестами. Не убирать работающий PNG/TGA loader вместе со старым catalog builder. Не отключать строгие проверки и не удалять регрессии ради зелёного CI. Отдельно проверить согласованное обновление app/index/classic scripts/dynamic modules: index на прежней точке использовал v=0.9.1, импорты модулей без версии, и чистка сама по себе не решает смешение кэша.
