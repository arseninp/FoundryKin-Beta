## Что действительно работает сейчас, а что только подготовлено

В fk-app.js save(k,v) и commitData(next) синхронно пишут localStorage.setItem. Импорта fk-pack-writer.mjs нет. Контроллеры списка и текстур вызывают commitData с writeOptions, но сам commitData пока их не использует. Host бэкапов тоже получает этот синхронный callback. Значит межвкладочная защита D02 не включена.

Форма: mountPackForm вызывает options.save({signal}), допускает boolean/Promise<boolean>, блокирует повтор, имеет leave/rollback и busy. Текущий shell передаёт save:function(){return save(KEY,data)}, игнорирующий options. Форма до результата меняет mutable data/pack и при отказе откатывает поля/добавление; будущая интеграция обязана учитывать это, а не просто заменить функцию async.

Writer: createPackWriter({storage,locks,key}) читает исходную сырую строку и нормализованный frozen snapshot; write(base,next,{signal}) клонирует/нормализует candidate, использует exclusive lock key+':write', внутри сверяет raw с base, затем пишет. Возвращает новый snapshot. Коды: PACK_SNAPSHOT_INVALID, PACK_LOCKS_UNAVAILABLE, PACK_WRITE_CONFLICT. Без Web Locks безопасной записи не обещает. Все писатели одного ключа должны соблюдать общий lock; старые вкладки/прямые записи этим автоматически не исправляются.

snapshot.value глубоко заморожен; его нельзя без адаптации сделать live data нынешней мутирующей формы. Не терять различие base persisted snapshot, mutable live state и локального draft. После конфликта нельзя бездумно перечитать/перезагрузить UI, уничтожив рисунок или поля, либо перебазировать старый полный data и затереть чужие изменения. Конкретное пользовательское восстановление/повтор после конфликта ещё нужно довести.
