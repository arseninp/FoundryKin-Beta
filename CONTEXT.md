## Как работать с владельцем

Владелец — куратор, не программист. Пишем по-русски, решения по коду выбирает ассистент. Не просить разбирать исходники. Прочитать [правила](docs/review-principles.md).

Одно замечание о коралле/древесине/цвете/стадии означает проверить всю аналогичную группу. Не объединять разные материалы без запроса. Waxed- и infested-варианты идентичны обычным по ресурсам и должны уйти из видимого каталога (решение владельца); конкретные связи подтверждать по данным, не терять уникальные файлы, не ломать открытие сохранённых паков.

В конце ответа — короткий английский список названий объектов для поиска; не пути JS. Язык интерфейса: на английском всё английское, на русском русское; имена файлов и игровые ID не переводятся; тексты идут через словарь `fk-i18n.js`.

## Изменения 0.9.x

- Включённый redstone torch: боковые плоскости используют полную область PNG (выступающие пиксели верхушки слева/сверху/справа); выключенный вариант прежний.
- Репитер и компаратор: основание 2 px, факелы, состояния просмотра: питание (По текстуре/Выкл./Вкл.), задержка 1–4 у репитера, сравнение/вычитание у компаратора. Передний факел компаратора в Java-моделях имеет одинаковые координаты в обоих режимах; «поднят/опущен» в Bedrock не проверен.
- `fk-model-state.js` + `fk-model-state.css`: панель состояний открывает тематическое окно через общий менеджер `FKM` (галочка у выбранного, закрытие по выбору, фону, Back). Значения хранятся в памяти и не записываются в PNG/паки.

## Согласованные, но ещё не сделанные решения (main)

1. Состояния и выбор PNG — разные действия. Выбор текстуры не должен выдвигать поршень, менять направление серного острия или питание механизма. Сейчас поршни и острие всё ещё читают выбранный слот; репитер/компаратор в режиме «По текстуре» тоже. Перевести всё на явные параметры панели и удалить прежнюю связь, не оставлять два способа. Опционально действие «Показать на модели».
2. Правило моделей: части одного объекта показываем вместе (бамбук, цветок со стеблем — не трогать); альтернативные варианты — по одному через меню (стадии роста/трещин, направление, поршень сложен/выдвинут, рамка Края с глазом/без, крючок с леской/без).
3. Аметист: сейчас рисуются сразу четыре маленьких кристалла (`fk-shapes.js`). Заменить одной карточкой семейства и параметром «Стадия роста»: маленький/средний/большой бутон/друза; одна модель по центру.
4. Метка `• icon` / `• иконка` рядом с именем файла слота, только для явно связанных предметных иконок (не угадывать по папке или имени; не любая carried-текстура — иконка). Имя файла не меняется.
5. Кнопка «Общие текстуры ⓘ» / Shared textures над просмотрщиком у действительно объединённых групп (пример — тыква): тематическое окно только с текстом на той же странице, через словарь EN/RU. Смысл: выбор файла = что редактируем; параметры просмотра = какой вариант показан; изменение общего файла влияет на все варианты.
6. Проигрыватель кадров, отдельно от состояний: `← ▶/⏸ →`, N кадров вертикальной ленты; для часов и компаса — простой циклический показ кадров без симуляции игры; для анимаций с описанием Bedrock (flipbook) — их порядок и длительности. Не считать любую высокую картинку анимацией; при рисовании пауза; кадры/скорость не отмечают PNG изменённым; экспорт сохраняет всю ленту. Не реализован.
7. Пузыри названий в Find: `-webkit-line-clamp:2` в `index.html` убрать, высота по тексту (1/2/3+ строк). Не сделано.
8. Открытые вопросы владельца: как фильтровать/искать совместные наборы (канонический вариант + перенаправление старых ID, а не удалять имена). Ассистент рекомендует: одна каноническая карточка, старые имена находят её, старые ID открывают обычный вариант.

## Подтверждённые дефекты из аудита (не исправлены в main)

- `openTexture` игнорирует сохранённый ID объекта и берёт первый по пути.
- Add/удаление/редактирование меняют память до сохранения без отката при отказе хранилища.
- Асинхронная замена PNG и замена по индексу могут попасть не в тот слот.
- Ресурсы объекта приводятся к общему разрешению.
- `auxiliary` (`end_gateway`, `lava_cauldron`) не доходит до каталога.
- Потеря иконок: у sunflower/lilac/rose_bush/peony carried-ресурсы удалены в fixtures; у pitcher_plant не сохранён `pitcher_plant_carried`; `carried_textures` в объектной форме (grass_block, dispenser, dropper, dried_kelp_block) молча теряется; нет иконок у brewing stand, cake, campfire, soul campfire, cauldron, flower pot, hopper, lever, reeds, kelp, nether wart, hanging roots, nether sprouts, frame→item_frame, glow_frame→glow_item_frame, sweet_berry_bush→sweet_berries, torchflower_crop→torchflower_seeds, табличек.
- Legacy-проверка диагностическая, не блокирующая; семейства не сверяются с хешем каталога; `validate` не реагирует на CSS и `data/catalog-families/**` (на `main`).
