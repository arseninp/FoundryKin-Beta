## Продукт и сохранение

Мобильный веб-редактор текстур Minecraft Bedrock и сборщик .mcpack. Владелец проверяет на Android. Адрес: https://arseninp.github.io/FoundryKin-Beta/app.html.

Путь: Create → создать/импортировать пак → открыть пак → Find → блок → редактирование → Add. Рисование само не сохраняет в пак. PNG скачивается из редактора; .mcpack экспортируется из списка паков. При выходе с недобавленными правками есть предупреждение, затем поиск восстанавливает данные активного пака. Полный регрессионный тест этого пути ещё нужен.

## Правила работы

- Русский язык, коротко и по делу; один обоснованный путь. Ответы без длинных пересказов.
- Каждая запись кода — новая версия: обновить FK_V и все ?v= в app.html и index.html (fk-app.js сверяет версию скрипта с FK_V). Документация версию не повышает.
- Не более 25 000 байт UTF-8 на файл. Сейчас fk-core.js 22 590 Б, fk-catalog.js 10 931 Б, fk-grid.js 10 729 Б, fk-shapes.js 3 738 Б. Не сжимать код ради лимита; переносить по ответственности.
- Любая запись в GitHub: подтверждение инструмента с полными аргументами, затем вызов с теми же байтами. Инструмент не умеет патчить — каждый файл пишется целиком. Поэтому по возможности менять мало файлов и объединять в один коммит.
- После записи сверить размеры файлов по SHA нового коммита. Git blob SHA: SHA-1 от b'blob ' + str(len(bytes)).encode() + b'\0' + bytes.
- Перед записью JS проверять синтаксис (node --check), для новых модулей — тест в node с заглушкой THREE. Это не заменяет Android-проверку.
- Не утверждать «работает на телефоне» по синтаксису или совпадению размеров. Отдельно писать, что проверено, а что нет.
- Никаких PATCHES, текстовых замен HTML, перевода готового DOM поверх базы, наблюдателей для исправления чужой разметки.
- Общие шрифт, палитры и шапка — fk-base.css. Модели блоков — только fk-shapes.js; не копировать построители в другие файлы.
- Документы обновлять по просьбе владельца. Не переносить незаписанное в «готово».
- GitHub Pages иногда публикует с задержкой: если версия на телефоне старая, смотреть Actions → pages build and deployment и открывать app.html с параметром ?x=N.

## Модели и подписи слотов

Модель плоская/крестообразная определяется по имени блока: список растений в fk-catalog.js (регулярное выражение + эвристика «одна текстура, звук grass, нет isotropic/carried/ambient_occlusion_exponent»), особые списки в shapeKeysFor (candle, carpet, rail, decal). В blocks.json нет признака геометрии, поэтому новые блоки Mojang могут попадать в куб, пока их нет в списках. Не классифицированы, по предположению: pointed_dripstone, sulfur_spike, pale_hanging_moss, big_dripleaf.

slotLabels берёт имена из файлов (путь, расширение и общий начальный префикс убираются, _ → пробел); при нескольких ключах назначения подпись составная (top + bottom). Известный недочёт: боковая текстура без суффикса (например log_acacia) подписана полным именем, а не «sides». Решение, если понадобится: подпись по набору граней (up+down → top + bottom, четыре боковые → sides, все шесть → all), без словаря суффиксов.

## Хранилище и ограничения

fk070_packs = {active,packs}; fk070_settings — тема, адрес редактора, язык. Пак: id/name/author/desc/version/game/icon/textures; текстура: path без textures/ и расширения, data URL, иногда obj/all. Импортированные UUID: keep/mod.

fk_hist — история до 20 цветов; fk_brush — размер кисти. Кэши: foundrykin.catalog.v3 (хранит b и p, но не cr), foundrykin.exist.v2.

localStorage ограничивает размер; импорт ориентировочно 2–3 МБ. Очистка данных браузера удаляет паки. Нужны интернет/CDN и WebGL; PWA и гарантированного офлайна нет. Не советовать очищать данные ради обновления интерфейса.
