## Что делали и где остановились

Доделывали участок D02: безопасное сохранение паков и явное восстановление после конфликта между вкладками без потери открытого черновика. Это не общий UI-рефакторинг, не новые функции и не завершение всего D02.

Writer уже подключён через packCommitter и единый commitData в fk-app.js. Прямой shell save допускает только настройки; старые утверждения TODO.md и docs/d02-handoff.md «writer не подключён» и «следующий шаг — начать сохранение из редактора» устарели. Не начинать эту работу повторно.

В main записаны:
- fk-pack-commits.mjs: reloadSaved требует confirmed:true, запрещён при pending write, проверяет сохранённый active; при удалённом паке отказывает до публикации данных. Коммит aba4c81115b10e87de90b8f1b33e6e3ad9dc081a.
- fk-pack-recovery.mjs и .css: одно окно конфликта, «Оставить черновик» либо явно прочитать актуальные паки; нет автоматического сохранения. Коммит 24d9b8a9da8bd808c697cb7aca021b5a1dab3dbb.
- fk-pack-recovery-host.mjs: busy/context/editor-token guards. Коммит 4331ac68881c48c55c0191f980d461717bd6c7c2.
- fk-app.js: PACK_WRITE_CONFLICT открывает recovery, исходная ошибка передаётся дальше; после чтения обновляются только текущие списки/экран бэкапа, но не fillEdit/loadEditor/FKE.reset. Смена экрана/режима закрывает устаревшее окно. Коммит 660abae465687f3fd707142d6d9761d095688bb5; размер shell 24434 байта.

Не делать auto-rebase и не повторять старый candidate после чтения. Повторное сохранение — отдельное действие пользователя с новым кандидатом из актуальных данных. Поля или текстуры редактируемой карточки могут заменить изменения другой вкладки: предупреждение об этом включено в подтверждение. При удалённом паке нельзя молча переключать черновик на другой пак.

## Проверки и оставшаяся приёмка

По переписке перед подключением прошли временные проверки: 12 для UI (fake DOM), 12 для host (подставные dialog/editor/storage API), 8 для shell callbacks (подставные host/committer). Это не постоянный набор тестов, не полный сквозной прогон оболочки, не Android-приёмка и не новый зелёный CI. Последняя запись shell проверена через saved diff; результаты более поздних прогонов не выводить из этих чисел.

Следующий чат должен завершать проверку этой реализации, а не создавать очередные подготовительные компоненты:
1. Сверить актуальные main/app.html/fk-app.js и импорты; прочитать реальные writer, committer, form, editor-save, recovery и backup-host перед сквозными проверками.
2. На изолированных данных проверить: конфликт → отказ/подтверждение чтения → новый ручной save; существующий и новый пак; сохранность полей/иконки и рисунка/истории; чужие изменения других паков и backupEntries не теряются; удалённый активный пак; busy/abort/смена контекста; нет успеха и markSaved при отказе записи.
3. Запустить имеющиеся проверки без ослабления. Новые permanent tests — только после согласования. Отдельно проверить нативный dialog, фокус, темы, мобильную компоновку, реальную работу двух вкладок/Web Locks. На данных владельца разрушительные операции не выполнять.
4. Только по доказательствам закрывать критерии D02. Pages SHA и текущий CI здесь не подтверждены. Не объявлять весь D02 завершённым по одному подключению recovery.
