# ARCHITECTURE — FoundryKin 0.8.40

База: main, код 1053bdb479b1866d5b9d7456f4c792447aab85d6. Запуск app.html. В корне 12 файлов приложения и 5 документов; каждый файл меньше 25 000 Б.

## Загрузка

Оболочка: fk-style.css, затем общая fk-base.css; FK_V; fk-i18n.js → fk-editor.js → fk-app.js → JSZip 3.10.1.

Редактор — один iframe с index.html?v=FK_V. В index.html локальные стили редактора, затем fk-base.css; скрипты fk-i18n.js → three.js r128 → fk-catalog.js → fk-core.js → fk-tools.js → fk-grid.js → fk-help.js. Собственные подключения версионированы. Не менять порядок без проверки зависимостей.

НЕТ runtime PATCHES/NEWPATCHES, строковых якорей, srcdoc и внедрения тела функций. Монолитная старая index.html больше не является базой. В документах/истории встречаются старые версии — не возвращать их механизмы.

## Общий интерфейс для новых разделов

Подключать fk-base.css после локальных стилей. Шапки: fk-header и позиционный модификатор fk-header--shell либо fk-header--find. Общие дети: fk-header-back, fk-header-bubble, fk-header-field, fk-header-help, fk-header-action. Кнопки ⋮ внутри шапки используют общий стиль fkHelpBtn.

Высота, ширина Back, размер SVG, gap, поля, отступы 24/8, скругления и резерв контента задаются --fk-header-* только в базе. Назначения ширины/высоты Back по отдельным ID запрещены. Размер одинаков, но позиционирование оболочки и Find различается. Внешняя страница и iframe — разные CSS-документы; оба должны подключать одну базу.

Montserrat, --bg/--panel/--ink/--mute/--line/--acc/--find/--red определены в базе. --find ссылается на --acc. Не дублировать палитры и font-family в страницах. Компонентные размеры карточек, холста и инструментов пока локальны; полная унификация всех стилей ещё не сделана.

## Границы API

- FKE из fk-editor.js — API оболочки: open, editTexture, info, getMode/setMode, reset, ready/busy, files/current/objInfo, dirtyNow/markSaved, closeMenu, scrollY, pendingEdit и doc (диагностика).
- FKAPI принадлежит iframe: state, subscribe, setMode, cur/files, loading/loaded, openTexture, stats, grid, ctx, version/pending/edits/busy.
- FKAPI.ctx — узкая связь инструментов с холстом, разрешением, историей и сообщениями. fk-tools не должен копировать внутренние переменные ядра.
- grid() даёт каталог, файлы/dirty, select/load, edited, discard/setPack, obj и shapeFor.
- FKAPP.migrate группирует импортированные текстуры после получения каталога.
- FKM — одно открытое меню и интеграция с history. Back приложения сначала закрывает меню, затем выходит из редактирования.

Статус каталога — loading/ready/failed/empty, источник cache/network/file, ошибка — code/detail. Не определять состояние по тексту интерфейса.

## Модель данных и селекторы

Обычные грани группируются по одинаковому пути текстуры; один слот/холст может обслуживать несколько граней. Метки форм строятся SVG по SHAPES; названия доступны в title/aria-label. Слоты после 0.8.40 — только текст из файлов; slotLabels сохраняет составные назначения при нескольких ключах. Это не меняет faceMap или экспорт.

Find сравнивает содержимое data URL, не только длину. Позиция списка сохраняется при клике до setMode; при возврате догружаются карточки до нужной высоты. Повторный вход и открытие из списка пака требуют регрессии.

## Хранилище и внешние данные

localStorage: fk070_packs, fk070_settings, fk_hist, fk_brush, foundrykin.catalog.v3, foundrykin.exist.v2. Формат паков не меняли. Каталог и ресурсы — Mojang bedrock-samples, сеть/CDN; JSZip/three.js/шрифт внешние.

## Известный долг

- lastT используется и как время кадра, и как terrain-данные: разделить переменные.
- Кэш каталога хранит b/p, но не cr: при использовании кэша carried-данные могут отсутствовать до успешного обновления.
- fk-app.js местами меняет объекты до save; отмена записи не всегда возвращает память в прежнее состояние. У чтения иконки нет надёжного токена формы.
- Освобождение геометрий при build, фоновые кадры скрытого редактора, очередь превью и асинхронные гонки требуют аудита.
- Пересечения навигации, истории, состояния меню и загрузки iframe; единая версия диагностики не является проверкой байтов всех ресурсов.
- Разрешение в ensureFiles выбирается по старому правилу 16/32, а импорт PNG читает размер: полный цикл 64px ещё не доказан.

## Дальнейшая архитектура

Границы ответственности: app/navigation, editor/tools/history, catalog, render, storage, pack-io, help, i18n, shared UI. Это не требование создавать файл на каждую мелочь. Растущий код переносить по ответственности с явным API и удалением старой реализации. После готовности функционала провести предрелизную чистку всего набора, а не только внешнего CSS.
